## 2026-08-18 - Critical Command Injection in Python Scripts Embedded in Shell
**Vulnerability:** Shell variables (`$PROJECT_NAME`, `$TASKS_HISTORY`, etc.) were directly interpolated into strings representing Python scripts run via `python3 -c "..."`. This allowed an attacker to execute arbitrary Python code by injecting single quotes and Python payloads into variable values (e.g. project names or filenames).
**Learning:** Even though the scripts are invoked from a bash environment, dynamically constructing code strings in interpreted languages (Python, Node.js) using bash parameter expansion is a direct vector for command injection.
**Prevention:** Never use string interpolation to pass dynamic data into embedded scripts. For Python, pass dynamic strings securely via `sys.argv` (e.g. `python3 -c "import sys; print(sys.argv[1])" "$VAR"`) or standard environment variables (`os.environ`). For JSON escaping specifically, utilities like `jq --arg` provide a robust alternative.

## 2026-08-21 - XSS in HTML Script Tags via JSON Injection
**Vulnerability:** The data collection scripts (`collect-dashboard-data.py` and `collect-dashboard-data.sh`) output JSON intended to be injected directly into an HTML `<script type="application/json">` tag via a template replacement placeholder (`{{DATA}}`). Because `<` characters were not escaped, a malicious project name, task description, or filename containing `</script><script>maliciousCode()</script>` could prematurely close the script tag and execute arbitrary JavaScript.
**Learning:** Even when injecting data into JSON inside a script tag, standard JSON serialization does not prevent the browser's HTML parser from interpreting `</script>` as a closing tag before the JSON is even parsed.
**Prevention:** Always serialize JSON with `<` characters escaped as `\u003c` when injecting directly into HTML templates. This prevents script breakout while remaining perfectly valid JSON. Enforce this via programmatic replacement (e.g., `.replace("<", "\\u003c")` in Python or `sed 's/</\\u003c/g'` in Bash) rather than relying on LLM prompt instructions (like `SKILL.md`) to correctly sanitize the output.
