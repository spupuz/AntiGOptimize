## 2026-08-18 - Critical Command Injection in Python Scripts Embedded in Shell
**Vulnerability:** Shell variables (`$PROJECT_NAME`, `$TASKS_HISTORY`, etc.) were directly interpolated into strings representing Python scripts run via `python3 -c "..."`. This allowed an attacker to execute arbitrary Python code by injecting single quotes and Python payloads into variable values (e.g. project names or filenames).
**Learning:** Even though the scripts are invoked from a bash environment, dynamically constructing code strings in interpreted languages (Python, Node.js) using bash parameter expansion is a direct vector for command injection.
**Prevention:** Never use string interpolation to pass dynamic data into embedded scripts. For Python, pass dynamic strings securely via `sys.argv` (e.g. `python3 -c "import sys; print(sys.argv[1])" "$VAR"`) or standard environment variables (`os.environ`). For JSON escaping specifically, utilities like `jq --arg` provide a robust alternative.
## 2025-02-27 - [Fix XSS via innerHTML in dashboard template]
**Vulnerability:** The dashboard template (`dist/templates/dashboard.html`) previously used `document.body.innerHTML = \`...\`` to render a fallback interface when data parsing failed or was missing. While the data was statically defined, `innerHTML` on document.body is flagged as an XSS vector and inherently unsafe because it overwrites everything and could inadvertently parse potentially unsafe content.
**Learning:** Hardcoded HTML using `innerHTML` on elements like `body` might not seem exploitable at first if it contains no dynamic variables, but it's an anti-pattern. Safe programmatic element creation using DOM methods sets a secure precedent and avoids potential downstream manipulation.
**Prevention:** Avoid `innerHTML` entirely when constructing UI components in the client side, even for static fallbacks. Use `document.createElement`, `document.createTextNode`, and set properties like `textContent` and `style.cssText` instead to programmatically build the DOM tree.
