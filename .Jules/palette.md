## 2026-08-22 - Critical ARIA context missing for visual progress bars
**Learning:** In the OmniState custom HTML dashboard, the token savings and task progress visualizations were built using `div` tags styled with Tailwind CSS to look like progress bars. Because they were not native `<progress>` elements, screen readers had no semantic context for them, treating them as generic empty `div`s. We learned that adding ARIA attributes (`role="progressbar"`, `aria-valuemin`, `aria-valuemax`) is not enough unless `aria-valuenow` is dynamically updated via Javascript alongside the CSS width property, which ensures visually impaired users receive the identical metric feedback as sighted users.
**Action:** When implementing visual progress bars using custom HTML elements (e.g. filled `div` elements) in this specific app's dashboard components, always attach ARIA progressbar attributes to the wrapper container and dynamically sync `aria-valuenow` via JavaScript to maintain screen reader accessibility.
